## Что представляет собой проект

**ETRNL** — статическое приложение для изучения немецкого, английского и русского. Работает при открытии [index.html](index.html) через `file://` и на статическом хостинге. Сборки и серверной части нет. На HTTP(S) приложение кеширует оболочку, общие данные и все языковые пакеты через service worker. На `file://` файлы загружаются локально напрямую.

У пользователя есть **I know** и **I learn**. Доступны все шесть направлений. По умолчанию **RU → DE**. Интерфейс английский, а значения, переводы примеров, пояснения и учебные подсказки следуют **I know**. Озвучка следует языку произносимого текста. При смене изучаемого языка приложение загружает соответствующий пакет и открывает ближайшую доступную страницу, если текущая карточка или тема в нём отсутствует.

## Прогресс, синхронизация и правила данных

- Хранилище разделено по изучаемому языку. Немецкий использует `gt.progress.v1`, английский — `etrnl.progress.en.v1`, русский — `etrnl.progress.ru.v1`. Общие настройки лежат в `etrnl.settings.v1`. При повторном использовании записи сохраняй её ID. Ключи обычной карточки — `<id>#rec` и `<id>#prod`, ключ упражнения — `<id>`.
- **Export** формирует общий JSON. **Import & merge** объединяет прогресс, отдаёт приоритет состоянию Known, для карточек повторения учитывает `last`, `reps`, `due` и сохраняет самое раннее `added`. **Replace** заменяет импортируемый прогресс. Для работы с реальным прогрессом используй экспорт перед заменой.
- **Google Drive OAuth** использует приватную `appDataFolder` и разрешение `drive.appdata`; OAuth-токен хранится в памяти. Для облачной синхронизации нужны HTTP(S), настроенный OAuth-клиент и разрешённый адрес приложения. **Синхронизация папки** использует File System Access API и сохранённый в IndexedDB доступ к JSON-файлу. Реальная синхронизация с Google Drive и между устройствами в текущих проверках не выполнялась.
- Для новых карточек сразу добавляй значения и переводы примеров на оба языка **I know**. В примерах `[[…]]` выделяет целевое слово для контекстного пропуска. В русском `+` ставится перед ударной гласной, сама `ё` передаёт ударение. Для `why` указывай степень уверенности, источник и подтверждение. Для `meaningType` нужны пояснение и примеры.
- Сохраняй английский интерфейс, принятую тёмную палитру с голубым акцентом, мобильную навигацию и структуру вкладки **User**. Русский используется для общения и handoff-документации, английский — для кода и комментариев.

## Проверка и известные ограничения

- При сборке этого документа загружены все три пакета через манифест. `GT.validatePack` и `await GT.validateLinks()` вернули 0 предупреждений, дублей ID, отсутствующих целей оверлеев и ошибок загрузки. Проверено наличие переводов значений и основных примеров на всех шести направлениях.
- Наличие перевода основных полей и отсутствие `.fb-tag` не подтверждают перевод каждого пояснения. Уже известный пример — блок **Structure** карточки `en:comfortable:adj:physical` при немецком **I know**. Он может показать русское примечание без метки.
- В предыдущих этапах Chrome с отдельным профилем проверил Learn, Review, Practice Studio, переключение локалей, `file://` и офлайн-перезагрузку. В последнем изменении BYS проверены положение кнопки, три версии статьи, независимый выбор её языка и переносы на ширинах 320–1440 px. В тестовых размерах окна у проверенных абзацев не было последней строки из одного слова.
- В рабочей папке `git rev-parse` не обнаружил Git-репозиторий. Доступен Node.js. Лаунчер `py` не находит системный Python, но Python есть в комплекте Codex. Для браузерных проверок использовался временный статический HTTP-сервер на Node.js. Для каталога English запускай `node --test english/tests/validate.cjs`.
- После изменений файлов приложения повышай `VERSION` в `sw.js` и проверяй **Settings → Data**. Для тестов прогресса используй отдельный профиль браузера или тестовый адрес.
