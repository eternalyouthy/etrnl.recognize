## Требования и решения пользователя

- Общение с пользователем на русском. Интерфейс приложения на английском; изучаемый язык — английский; переводы, учебные пояснения и объяснения ошибок — на русском. Код и комментарии к коду — на английском.
- Изменять только `english/`. Корневые `index.html`, `js/`, `css/`, `data/`, `sw.js` относятся к немецкому приложению и разрешены **только для чтения** как референс. Не переносить туда английские изменения, не обновлять немецкий service worker.
- Пользователь прямо запретил управлять его компьютером и Chrome для проверок. Использовать отдельный скрытый in-app browser (`iab`, `visible: false`) и отдельный QA origin. Не переключать его окна, вкладки, мышь или клавиатуру.
- Сохранять установившийся ETRNL-дизайн. Последний утверждённый образец — немецкая версия: чёрный фон, ледяной голубой акцент, квадратные тонкие рамки, моноширинные подписи с разрядкой, центрированные вкладки с номерами 01–06 и тонкими SVG-шевронами. Промежуточные варианты с мелким Unicode-символом или иконкой списка были заменены.
- Тематические экраны должны оставаться простыми: список тем слева, обзор темы, Browse и изучение по одному слову. Не возвращать на первый экран темы большой каталог карточек, открытые панели источников или сложные настройки.
- При дальнейшем наполнении пользователь выбрал **равномерно все разделы**, а не только IT/Security.
- Не менять существующие ID, не пересоздавать карточки, не сбрасывать прогресс. Темы используют ссылки на единый каталог, а не копии слов.

Корневой `HANDOFF_PROMPT.md` описывает немецкое приложение и содержит исторические данные и другой scheduler. Не использовать его как актуальный handoff английской версии.

## Запуск и проверки

Приложение — vanilla HTML/CSS/JS с последовательными `defer`-скриптами. Нет сборки, npm-зависимостей, runtime fetch данных или подключения немецкого кода. Вход: `english/index.html`; можно открыть напрямую или через локальный сервер.

Из корня проекта:

```powershell
node english/tests/serve.cjs
node english/tests/serve.cjs 8768
node --test english/tests/validate.cjs
node english/tests/summarize.cjs
```

Первый вариант сервера использует `http://127.0.0.1:8766`, второй — порт 8768. Сервер привязан только к loopback и обслуживает только `english/`. Если порт занят, выбрать другой свободный порт; не завершать чужой процесс.

Для скрытого браузера сервер внутри sandbox ранее был недоступен. Запуск того же сервера вне сетевой изоляции решил проблему; затем использовался отдельный `http://127.0.0.1:8768`. Не предполагать, что старый процесс сервера или browser handle ещё жив.

`localStorage` привязан к origin: `8765`, `8766`, `8768` и `file://` не следует считать общим хранилищем. Не импортировать пользовательский прогресс в QA и не очищать его origin. Для переноса между способами запуска есть штатный Export/Import.

Публикация, интеграция с немецким host, git commit/push/merge в рамках этой работы не выполнялись.

## Навигация и сценарий изучения

- LANGUAGE: Words, Grammar, Roots.
- PROFESSIONAL: Work & Office, IT & Development, Infrastructure, Security, B2 Business English.
- EXPRESSIONS: Chunks, Idioms, Everyday Phrases.
- PRACTICE, REVIEW и STATS — отдельные вкладки.

Меню открываются наведением мыши, на мобильном — нажатием. Поддерживаются клавиатура, Arrow Down и Escape. На узких экранах навигация переносится на отдельные строки.

В тематических разделах sidebar показывает темы текущего раздела и Known/Total. В Roots и других справочных экранах восстанавливается прежний sidebar с семействами, аффиксами и инструментами.

Обзор темы: New / Learning / Known / Due Today, большая кнопка Learn до 10 новых, Browse all, Practice now и Review при наличии due. Speaking practice сохранён в свёрнутом блоке.

Learn: слово/выражение, перевод, произношение, WHY?, примеры, Note, структура, ссылки на доступное семейство, вариации выражения. Источники и уровень свёрнуты. Неподтверждённые этимологии и русские связи не выдумывать. Для отдельных слов может быть только один пример: не фабриковать второй из словаря или литературы.

Маршруты:

```text
#/words/health
#/words/health/learn
#/words/health/browse
#/words/health/item/<encoded-entry-id>
#/professional/work
#/professional/dev
#/professional/infra
#/professional/security
#/professional/business
#/idioms/people
#/everyday-phrases/respond
#/practice?topic=professional%3Asecurity
#/review?topic=words%3Ahealth
```

Шаблон overview/learn/browse/item действует для всех тематических разделов. Сохранены `#/it`, старые `#/it/<topic>`, `#/chunks`, `#/vocabulary`, `#/roots`, `#/family/<id>`, аффиксы и классические корни. `#/stats` — alias для `#/progress`. Старые Practice-ссылки с `it:<topic>` сохраняют исходную область темы.

## Данные и прогресс

- Canonical ID: `en:<headword>:<pos>:<sense>`. Для разных значений нужны отдельные sense keys. Не создавать второй ID для того же значения ради другой темы.
- Тематический ключ: `words:health`, `professional:security` и т. п. `entryIds` — массив ссылок на общий каталог. `topicByKey`, `topicEntries`, `sectionEntries` используются повторно.
- Существующие шесть vocabulary categories сохранены. Professional — тематическая группировка; не нужно создавать копию каждого слова в новой category.
- Namespace `ETEnglish`, ключ localStorage **`etrnl.english.progress.v1`**, `schemaVersion: 1`, `language: 'en'`. Не читать/писать немецкие `GT` / `gt.*`.
- Карточки: `<canonical-or-reference-id>#rec` и `#prod`. История, grade и due учитываются отдельно по направлениям.
- Английский scheduler — простой интервальный, **не FSRS**. Не переносить немецкую FSRS-реализацию без отдельной задачи.
- **Know it**: `store.markKnown(id)` выставляет `known: true` обоим направлениям. Не увеличивает количество оценок; сохраняет предыдущие поля истории. Known исключается из due.
- **Learn it**: `store.enroll(id)` добавляет оба направления; существующий Known снимается для выбранных направлений, due становится текущим. Не дублирует уже имеющиеся карточки.
- **Later**: `store.defer(id)` записывает timestamp в `later`. Слово остаётся New, не получает карточку или оценку, перемещается после остальных unseen в следующих Learn queues.
- `known` и `later` — совместимые необязательные поля version-one backup. Импорт старых файлов поддержан; новый импорт валидируется до изменения данных. Не терять эти поля при следующих изменениях.
- Learn по умолчанию берёт unseen в допустимом учебном диапазоне; известные словарные C1/C2 не попадают в обычные новые сессии. Browse показывает также расширения.
- Ответ в Practice/Review сам по себе не меняет расписание: запись оценки происходит после Again / Hard / Good / Easy. Grammar имеет оба направления, affixes — только recognition.
- При сбое localStorage приложение работает в памяти и показывает сообщение с предложением экспорта.

## Как добавлять следующий пакет

1. Сначала проверить каталог на существующее значение и повторно использовать ID. Не перегенерировать прежние записи.
2. Добавлять тематические данные по модели `content-expansion-01.js`: headword, POS, русский смысл, авторский английский контекст, перевод, usage/WHY?. Для выражений нужны также естественная вариация и её перевод.
3. В каждом упражняемом примере должна быть ровно одна пара `[[target surface form]]`. Принимаемый ответ должен грамматически подходить именно этому контексту, а не только совпадать с леммой.
4. Добавлять ID в нужный topic. Для новых семейств использовать существующую модель графа; морфемные части должны восстанавливать написание. Не смешивать этимологию с современной словообразовательной связью.
5. Грамматическая тема содержит объяснение, пример/перевод, recognition question/options/answer/explain, `production{question,answer,explain}` и справочную ссылку. Делать ожидаемый ответ однозначным формулировкой задания.
6. Если добавляется новый файл, включить его перед learning/app в `index.html` и в список `scripts` в `tests/validate.cjs`.
7. Обновить счётчики/ожидания тестов и документы. В тестах есть намеренно точные числа; изменять их вместе с данными, сохраняя проверки качества и совместимости.
8. Обратить внимание на `skipExpansion` и `originalScripts` в тестах: сейчас они исключают конкретные файлы последних расширений для сравнения с предыдущими состояниями. Новый пакет не должен незаметно попасть в baseline, с которым сравнивается сам же.
9. Выполнить validate + summarize; затем проверить несколько новых слов, выражение, семейство и grammar production в отдельном браузере. Обновить верх `VALIDATION.md` с фактическими результатами.

Следующий полезный приоритет при запросе дальнейшего наполнения — менее насыщенные существующие темы Words и ситуации общения, продолжая равномерно поддерживать Professional, Expressions, Grammar и Roots. Новые верхнеуровневые разделы для очередного пакета не требуются.
